## テーマ

`console.log(obj)` の表示結果が、DevToolsを開くタイミングによって変わる理由の調査

## やったこと

以下のHTMLを題材に、DevToolsを「後から開いた場合」と「最初から開いていた場合」で `console.log(life)` の出力結果が異なる理由をAIと一緒に考察した。

```html
<script>
  let life = { answer: 42 };
  console.log(life);
  life.answer = 0;
  console.log(life);
</script>
```

- 後から開いた場合 → `Object` `Object`(展開すれば両方 `{answer: 0}`)
- 最初から開いていた場合 → `{answer: 42}` `{answer: 0}`

## わかったこと

- `console.log` は呼ばれた時点では「オブジェクトへの参照」と「スタックトレース」を記録するだけの軽い処理。
- DevTools(CDPのRuntimeエージェント)が接続されていると、呼び出し時点でプロパティを走査して**プレビュー(スナップショット)**を作る。これはコストがかかる処理。
- DevTools未接続時はこのプレビュー生成をスキップ(誰も見ていないのに毎回走査するのは無駄なため)。後から開くと参照先の**今の状態**しか見えないので、両方同じ値に見える。
- 接続中は呼び出し**その瞬間**の状態をスナップショットするので、2回のログで異なる値(42→0)が正しく記録される。
- これはECMAScript仕様ではなく、Chrome DevTools側の実装上の最適化(必要な時だけコストを払う設計)。

## 学び・メモ

「参照を溜めるだけ」と「呼び出し時にスナップショットを取る」という2つの動作モードがある、という理解がポイント。デバッグ時にオブジェクトの状態を追う際は、この挙動差を意識しないと「あれ、値変わってないぞ？」と勘違いしやすい。

## やりとりの記録(プロンプトと回答)

### Q1

**状況・疑問**
以下のHTMLをChromeで開いたとき、DevToolsを開くタイミングによってコンソール出力が変わった。

- 後からDevToolsを開いた場合 → 結果1
- 最初からDevToolsを開いていた場合 → 結果2

```html
<!DOCTYPE html>
<html>
  <body>
    <script>
      let life = { answer: 42 };
      console.log(life);
      life.answer = 0;
      console.log(life);
    </script>
  </body>
</html>
```

**結果1**

```
index.html:5 Object
index.html:7 Object
```

**結果2**

```
index.html:5 {answer: 42}
index.html:7 {answer: 0}
```

**自分の仮説**

- 結果1は `console.log(life)` の出力結果であり、`life` が参照するのが `Object` であるため、こう表示されていると思う。
- 結果2はすでに開発者ツールを開いているので、順次 `console.log(life)` が溜まらずに処理され、`life` の中身が表示されるのではないか。
- ただし結果2の場合も `Object` と表示されるのではと思ったが、なぜ中身が表示されるのかが疑問。
  **A1（要約）**
  違いは「プレビュー(スナップショット)がいつ作られるか」。DevTools未接続時はプレビューを作れず参照だけ記録するため、後から開くと両方"今の状態"(Object展開すれば`{answer:0}`)になる。DevTools接続中はconsole.log呼び出しの瞬間にプロパティ値をスナップショットしてプレビューを作るため、1回目は`{answer:42}`、2回目は`{answer:0}`と呼び出し時点の状態がそれぞれ固定される。

### Q2

**質問**
なんでDevToolsが開いているとプレビューを作るの？そういう仕様になっているということ？

**A2（要約）**
ECMAScript仕様ではなく、Chrome DevTools Protocol側の実装上の設計判断。console.log自体は本来「参照とスタックトレースを記録するだけ」の軽い処理だが、DevTools接続中はプロパティを列挙して人間が読める形に変換する「プレビュー生成」という重い処理が追加で走る。誰も見ていないのに毎回この処理をするのは無駄なので、未接続時はスキップ(軽量)、接続中は必要だからプレビュー化する、という「必要な時だけコストを払う」最適化になっている。
